# Motion Studio

🇮🇹 [Italiano](README.it.md)

A local, open-source app for creating motion-graphics videos and images with your coding agent (initially **Claude Code**). Describe what you want, pick channels and formats: the agent produces a dedicated recomposition for each format. Everything stays on your computer: projects are folders of JSON/Markdown files versioned with git.

## Language
Motion Studio is available in English and Italian. On first launch it uses your system language: the first of your preferred languages that Motion Studio supports, English if none is. Change it in **Settings → Language** (System / English / Italiano): the interface, the desktop menus and the messages of the terminal launcher switch language, and the agent replies, and writes the texts meant for you, in the chosen language. When the desktop app attaches to a Motion Studio that is already running, its native menu keeps the language it started with; the interface follows the change live. To add another language, see [CONTRIBUTING.md](CONTRIBUTING.md#adding-a-language).

Texts saved in the past (validation problems in a version, conversation messages, brand guidelines) are not translated; only new texts use the current language.

## Installation

**Desktop app (Electron).** Download the installer from the project's GitHub *Releases* page, once it is published (macOS: Apple Silicon `arm64` and Intel `x64`). Unsigned builds (those without the maintainers' certificates) need an extra step the first time:
- macOS: right-click the app, then **Open** (and confirm); a normal double-click is blocked by Gatekeeper.
- Automatic app updates (check at launch, install on restart) require **signed** builds on macOS; with an unsigned build, update by downloading the new version by hand.

**From npm.** `npx @motion-studio/cli` (the installed command is called `motion-studio`), once it is published. Publishing it requires the `motion-studio` npm organization. Until then, use the sources.

**From source.**
```bash
pnpm install
pnpm motion-studio        # build + start on http://127.0.0.1:4317 and open the browser
```

Launcher options (after the script name, e.g. `pnpm motion-studio --port 5000 --no-open`):
- `--port <n>` — port of the local server (1–65535, default 4317).
- `--no-open` — do not open the browser (if opening fails, the launcher prints the address to open by hand).
- `--print-url` — print the address of the Motion Studio that is already running, without starting another one (useful if you closed the tab).

The address printed at startup contains an access code (`#t=…`): open Motion Studio from that link. The browser remembers it; if the interface asks you to reopen it from the terminal link, use `--print-url`. The desktop app opens its own window.

Only one Motion Studio runs per configuration folder: if one is already running (from the terminal or as the desktop app), `motion-studio` prints `Motion Studio is already running: <address>`, opens it in the browser (unless `--no-open`) and exits, and the desktop app opens that address instead of starting another (if that Motion Studio quits, the app offers to restart).

## Requirements
- [Claude Code](https://docs.claude.com/claude-code) installed and signed in (`claude auth login`)
- Git
- FFmpeg (needed to render compositions into videos; stills need none; older creatives without it are shown as "unverified")
- For the CLI (`npx`) only: Google Chrome or Chromium, which renders the compositions. Without it, **Settings → System check** offers to download Chrome for Testing into Motion Studio's data folder, only after showing its size and with your consent. The desktop app renders with its own Chromium.
- Node.js 22+ for `npx` and the sources (not needed for the desktop app)

## How it works
1. In a project, open **Creatives → + New creative**, describe what you want, pick channels and formats and press **Generate**.
2. The agent works in `creatives/<date-title>/work/` and delivers, in `outputs/vN/compositions/<format>/`, one **composition** per format: a `composition.json` (scenes, tracks, text, shapes, images, video, audio, animations, optional HTML layers) and the `assets/` it uses ([full contract](docs/output-contract.md)). The agent never renders final media and never installs a renderer.
3. Motion Studio checks each composition (schema, files, duration against the brief): if something is off it asks the agent to fix it, up to 3 attempts in total; then it saves the version, even if incomplete. It then makes a storyboard (one small frame per scene) for each format.
4. The boards show the storyboards and play a **live preview** of the composition: no waiting for a render. A version starts as "Not rendered".
5. **Render ★** (or an export that needs it) renders the starred versions on your computer, outside the agent's sandbox: an mp4 (H.264, BT.709) for videos, an image file for stills (a png when the format allows it, else a jpg or webp it lists), with the encoding targets of each format. A render never blocks the agent: renders wait in their own queue, one at a time. A later change makes a new version, and the render of another version is never touched; rendering the same version again replaces its file.
6. Each version is a git commit of the project. From the creative's page you can open a format, add comments on a spot/moment, ask for changes, compare versions and restart from an earlier version. A creative made before compositions keeps its videos; at its next change the agent converts it to a composition (the chat says that this turn costs more tokens).

### Talking to the agent while it works
The composer stays active while the agent works.
- **Queue for after.** A message sent during a turn is added to the request queue and runs as the next request. It starts by itself only after a turn that saved a version; after a failure, Stop, cancel or an app restart it waits for **Run next** (after a restart each queued request needs its own). The console has no queue: a message to a running console turn is sent live or not at all. You can edit, remove and reorder queued requests.
- **Stop** stops the turn at once and cancels any open approval, so nothing is spent after it. The next request resumes the stopped session as a fork, so the agent knows what was left half done.
- **Stop and redirect** stops the current step and continues the same job with your new text.
- **Live messages and interrupt** (sent into the running agent without a restart) are **on by default for Claude Code 2.1.301 and newer**, the version checked with a real Claude Code on 2026-10-16 (`docs/superpowers/notes/2026-10-16-stream-input-probe.md`). Older or unknown versions keep the fallbacks: a message waits as the next request, and Stop and redirect stops the agent and resumes the session. A live message is read by the agent as soon as its current step ends; it shows "Sent" once written and "Delivered" only when Claude Code shows it took it. To switch either off, set `agentLiveInput` or `agentInterrupt` to `false` in the workspace's `.studio/settings.json` (there is no switch in the interface). The Doctor and `GET /api/agent/capabilities` say which path is active.

### Usage and tokens
Every agent job (creative turn, fix attempt, brand analysis, asset description) adds one line to `<project>/.studio/usage.jsonl` with the tokens Claude Code reported for that run and, when known, the cost at API list prices. The file is append-only and protected from the agent.
- **Tokens first, cost second.** The figure shown is input + output + cache-write tokens; cache reads are only in the details. On a Claude subscription the cost is shown as "at API prices it would be about …", since the usage counts toward your plan.
- **Where you see it:** a live counter on the running job, today's total in the top bar (it opens **Settings → Usage**), the activity center (per job, plus "Today · N tokens"), each version card in the conversation, each brand analysis, the creative's brief, and **Settings → Usage** (last 7 days, by project and by kind of work). The new-creative form estimates a range from your own past first generations.
- **Resumed sessions:** Claude Code reports cumulative cost for a resumed session, so each line stores the difference from the previous run of the same session; when it cannot be worked out the cost is left empty and marked as estimated.
- **Nothing invented:** jobs from before this feature have no figures ("Tracked since …"), and missing values show "—" or are hidden.
- **Large files:** a video whose bitrate is more than 1.5× a sensible target for its size (for example about 4 Mbps for a 1080×1920 reel at 30 fps) gets a "large" chip with the size, bitrate and target. It is a warning only: it never fails the output.

### Export
From the creative's page, **Export** copies the starred (★) version of each format into a folder of your choice (the desktop app also has **Choose…**). Each row shows the final file name, "★ vN" (and "vM newer" when a newer version exists), and "follows …" for a format that follows another: it is exported as its own file from its primary's ★ version. File names come from a pattern with the variables `{title} {channel} {format} {ratio} {v} {date}` (default `{title}-{format}-v{v}`, e.g. `launch-instagram-reel-9x16-v2.mp4`); each value is turned into a slug, other characters become `-`, the name is limited to 120 characters before the extension, `{date}` is the day shown in the dialog (`YYYY-MM-DD`), Windows device names such as `CON` or `NUL` get a `_` and unknown variables are left out (the dialog flags them). The dialog previews the names as you type and **Save as default** stores the pattern for the workspace. If two formats would get the same name (compared ignoring case) the export is refused: add `{format}`. Export never overwrites anything (if the name exists it appends `-2`, `-3`…) and refuses destinations inside the Motion Studio workspace. A ★ whose file is missing, a symlink or a hard link cannot be exported: the dialog disables it and the export refuses it before copying anything. A ★ composition that is not rendered yet (or whose render is out of date) is rendered first, with its progress shown, and then copied.

### Adding formats
If you add formats to the brief of an already generated creative and press **Generate** again, Motion Studio asks the agent to add only the missing compositions, reusing the sources already in `work/` and the same style as the previous version. A format linked to another one (for example TikTok following the Reel) needs no agent: it shares its primary's composition and render. On a creative made before compositions, adding only linked formats still needs no agent: they are copies of their primary's video, as before. Adding any other format, or regenerating, converts every format to a composition with the agent; the brief editor says so before **Save and regenerate**, since that turn costs more tokens.

### Variants: duplicate formats, languages, store pack
**Duplicate and reorder formats.** A creative can hold the same format more than once, for example two Stories or ten screenshots for one iPhone. In a format's view, **Duplicate format** copies the composition of the open version into the next free instance (`<format>@2`, up to `@20`; the first instance keeps the plain format id, so older creatives do not change) and saves it as a new version with no agent. From there the instance is iterated alone: in the chat with the format chips ("Applies to"), or in the editor; the other instances stay byte-identical. Each instance can have a **label** (up to 60 characters, edited in the brief editor), otherwise it shows the format name with "#2". The brief editor also reorders the instances (drag, or Move up and Move down) and removes them: removing keeps the saved versions. The order is the display and export order. Export names add the instance (`instagram-post-1x1-2`) when two files of the same format would collide.

**Languages.** In the brief editor (**Languages**) pick the original language and up to 10 languages to translate into (Latin, Cyrillic and Greek scripts, Chinese, Japanese, Korean, Hindi, Thai and more; right-to-left languages are listed but not supported yet). The **Languages** button of the creative then opens the panel:
- **Translate** starts a translation turn on the open version for the languages and formats you tick. The agent only answers with the translated texts (and, for long languages, a text scale); it never edits the composition, so positions, timings, colors and images stay those of the original. Motion Studio checks the result, and when a text does not fit its box it asks for a shorter one (up to 3 attempts).
- **Voice options**, per language: **Translate** (Motion Studio makes the translated voice-over with the voice service set in the brief, after a single confirmation for the whole turn listing the calls, characters and service; "Always for this project" applies), **Keep original** (the source voice stays) or **Mute**. Without a voice service or key, only Keep original and Mute are offered.
- **Review**: per format and language, a table with the original, the editable translation, its state (OK, outside the box, outdated) and a text-size slider (**fit**, 70% to 100%). Saving a translation writes only the overlay of that version and re-runs the checks; it never makes a new version of the composition. A translation that does not fit shows "Outside the box" until you shorten it or lower its size.
- **Preview**: the player and the editor have a language switcher that shows the translation on the live preview.
- **Fonts**: for scripts the original font cannot draw (for example Japanese), Motion Studio downloads the Noto Sans of that script from Google Fonts into `assets/fonts/` and adds it to the text clips of that language.
- **Newer versions**: a later version carries the translations whose source text is unchanged; the others are marked **Outdated**, and **Translate** only redoes what is missing or outdated. An outdated text is never shown as translated: the preview and the render use the original text for that clip and say so.
- **Render and export per language**: **Render** and **Export** accept the languages; files are named `<format>.<language>.<ext>` (the export pattern gets `{locale}` when the creative has languages). Rendering a translation with open problems or outdated texts asks for confirmation ("Render anyway") and marks it in the manifest.

**App store pack.** The **Store pack** is an entry of the formats list. In **New creative** it has its own row above the channel groups (search finds it too); in the brief editor of an existing creative it sits in the App Store group. It opens the assistant in a window, which asks for the app (name and a line), the stores (App Store, Google Play or both), the devices, the number of screenshots with a caption each, an optional preview video and the real app screens (images from the library, one per screenshot, or an explicit "no app screen"). It makes one format instance per screenshot and device, labelled "N · caption"; **Add to the formats** adds them to the chosen formats, next to any other format; a creative has at most one pack. Once added, the entry reads "Store pack · N screenshots" with **Edit** (the assistant again, with the current values) and **Remove**: Motion Studio recomputes only the pack's own instances (it adds the new ones and removes those no longer needed; versions already made stay in the history) and never touches formats you picked by hand. Store screenshots picked one by one are still normal formats, outside the pack and its export. The agent is told the pack is a series: same grid and style, caption on top, the app screen alone on the background, with no device frame (no Apple or Google artwork or logos; creatives made earlier with a frame keep rendering). In the creative's format column the pack's instances form one **Store pack** group, with App Store and Play Store as subgroups. **Export pack**, in that group's header, writes `<title>-store-pack/` with `AppStore/<device>/NN-<caption>.png`, `AppStore/preview.mp4`, `GooglePlay/<device>/…` and `feature-graphic.png`, plus a `README.txt` with the limits, the upload order and a note that Google Play wants a YouTube link rather than a video file (a language level is added when the creative has languages). Before writing each file Motion Studio checks the exact size, PNG or JPEG, no alpha channel (screenshots are flattened onto the background), and for the App Store preview 15 to 30 s, 30 fps, H.264 and an audio track (a silent one is added when the composition has none). A file that fails is skipped with its reason; the rest of the pack is exported. Store formats of the brief that are not part of the pack are not exported with it: the export result, the dialog and the pack's `README.txt` list them. Creatives made with the old **App store pack** card keep working, and the API route `POST …/creatives/store-pack` stays. The limits were read from Apple's and Google's public pages on 2026-10-14. Checked live: see `docs/superpowers/notes/2026-10-14-phase12-live-checks.md`.

### Identity formats: logo, favicon, app icon, social preview
The **Identity** group of the formats list has four formats:

| Format | What the render writes, in `outputs/vN/<format>/` next to the main image |
|---|---|
| **Logo** (`identity-logo`) | `logo.svg` and `logo.png` (1024 px on the long side, transparent) |
| **Website favicon** (`identity-favicon`) | `favicon.ico` (16, 32 and 48 px), `favicon.svg`, `apple-touch-icon.png` (180, opaque), `icon-192.png`, `icon-512.png`, `icon-512-maskable.png` (opaque, the drawing at 72%), `site.webmanifest` (theme colour from the brand's primary colour) and `head-snippet.html` with the tags to paste in your page's `<head>` |
| **App icon** (`identity-app-icon`) | iOS: `AppIcon-1024.png` (opaque) and `Contents.json`. Android: `ic_launcher-playstore.png` (512, opaque, for the Play Console), `ic_launcher_foreground.png` (432, transparent, the drawing at 66/108), `ic_launcher_background.png` (432, a solid colour), `ic_launcher.xml` (adaptive icon) and `mipmap-mdpi` … `mipmap-xxxhdpi/ic_launcher.png` (48 to 192 px) |
| **Social preview (Open Graph)** (`og-image-1200x630`) | a normal image, 1200×630, PNG or JPEG up to 5 MB; no set |

- **Vector first.** Logo, favicon and app icon are still compositions made of one full-frame SVG. Each SVG passes a strict check before it becomes an output: no scripts, `foreignObject`, event attributes, external references, embedded images or URLs in styles; at most 512 KB; text should be converted to paths (a `<text>` element is allowed with a warning, since its look depends on the installed fonts). A refused SVG goes back to the agent with the reasons; in the app you see a short summary, the English reasons are behind **Details**. Every PNG is drawn from the SVG at its exact size (never a big PNG scaled down). For the favicon and the app icon the agent may add a simplified `small` drawing, used up to 48 px. The icons that must have no alpha channel are flattened onto the composition's background when it is opaque, else the brand's primary colour, else white (with a warning). A drawing that leaves the safe zone of the maskable icon or of the Android foreground gets a warning; it never blocks.
- **Start.** Picking an identity format shows **Start**: **From the brand logo** (the default when the brand has a logo: the agent adapts it, with margins and a simplified version for small sizes, without redrawing it; a raster logo is redrawn as a faithful SVG and the conversation says so) or **From scratch** (a name or initials, optional style keywords, brand or free colours). A logo from scratch makes **3 concepts** by default (1 to 5), as separate instances `identity-logo`, `identity-logo@2`, `identity-logo@3`, so you can compare them and keep one (a creative made through the API with only `identity-logo` and a number of concepts gets the same instances); in the brief editor of an existing creative use **Add another** as for any format. The agent draws SVG: no paid image generation is used for logos.
- **View.** The format view of a favicon or an app icon switches between **Image** and **Sizes**: every file of the set at 1:1 and zoomed, the set's warnings, and the icon in context (browser tab at 16 and 32 px, iOS rounded corners, Android circle with the safe zone). A logo is shown on light and on dark side by side. Its status reads "Set ready · N files" once rendered.
- **Use as brand logo** ("Usa come logo del brand" in Italian), on a version of a logo or a favicon: after a confirmation (main logo or icon) Motion Studio checks the SVG again, copies it into `assets/brand/` and adds it to the brand kit at once, with the source `creative:<slug>/vN`; there is no proposal to approve. If the kit already has a logo of the chosen kind, that one is demoted (main logo to secondary, icon to other), so the kit keeps one main logo and one icon. The app icon set has no SVG, so it does not offer it.
- **Where the files go.** Web: the favicon files go in your site's root (the paths in `head-snippet.html` and `site.webmanifest` start with `/`). iOS: `AppIcon-1024.png` and `Contents.json` make the `AppIcon.appiconset` folder of your asset catalog (single-size format). Android: `ic_launcher.xml` goes in `res/mipmap-anydpi-v26/`, `ic_launcher_foreground.png` and `ic_launcher_background.png` in `res/mipmap-xxxhdpi/`, each `mipmap-<density>/ic_launcher.png` in the `res/` folder of the same name (the icon for Android before 8), and `ic_launcher-playstore.png` is uploaded to the Play Console.
- **Export.** The export of the creative copies each set as a folder named like the file (with its `mipmap-*` subfolders), next to the main image.

### Editing a composition directly
In a format's view, **Edit** (or **Open editor** on a board) opens the editor on the version shown. A format that follows another opens its primary's composition, and the header says which formats share it. The editor has the scenes (or, for a still, the layers) on the left, the stage with the live preview in the middle, the timeline below a video, and the **Inspector** and the **Chat** on the right.

- **What you can change:**
  - a text's content, font (one of the composition's, or a brand kit font that has a file: the file is added to the composition), weight (only those declared for the font), size, colour and alignment;
  - position, size, rotation and opacity: with the handles on the stage (with snapping to guides, the safe area and the frame), with the inspector's numbers, or by nudging with Alt+arrows;
  - timing: trim and move clips on the timeline (snapping, Alt disables it), with **Ripple** to push the later scenes when a clip grows; the scene order, when every clip lies in one scene;
  - the entry and exit animation presets;
  - an image, vector image, video or audio file, replaced from the project's library or uploaded there (a video shorter than the clip says so and offers "Fit clip to video"); a video's trim start and volume; an audio clip's volume and fades;
  - an HTML layer's parameters;
  - hiding and locking clips and tracks, and muting audio tracks.

  New clips, layers, custom animations, effects and new scenes stay with the agent: ask for them in the chat.
- **Undo and redo:** ⌘Z and ⇧⌘Z (Ctrl on Windows and Linux), never while you type in a field. A drag, or a burst of typing, is one step.
- **Save:** the pill "Draft · N edits" offers **Save as vN** and **Discard**.
  - Saving makes a normal new version (`origin: editor`) whose request is a summary of the edits, e.g. "Direct edits: Title text, font Schibsted Grotesk".
  - No agent runs and no tokens are used: the usage ledger gets no line.
  - The other formats are carried; formats that follow the edited one are checked again (one that can no longer follow, e.g. over its maximum duration, is unlinked and the chat says so).
  - Renders are carried only for unchanged compositions, and the storyboards are made again.
- **The draft is never lost by surprise:**
  - leaving the editor with unsaved edits (back, another format or version, a link, a chat message) asks "Save · Discard · Keep editing";
  - reloading or closing the page asks the browser's (or the app's) confirmation (in the app too for ⌘R and View → Reload), and a confirmed reload does lose the draft.
- **While someone else works:**
  - while an agent turn or a render of the creative runs, Save is not available (the core refuses it too);
  - if a turn or another save changed the same format meanwhile, Save is refused and the draft is kept; **Reopen on the latest version** discards it after a confirmation;
  - a turn on another format does not block the save.
- **Comments for the agent:** besides a spot of the frame, a comment can be on a clip (**Comment on clip**, or `C` with a clip selected) or on a time range (**Comment on range**, or `R`, or Shift+drag on the ruler), in the editor and in the format view. The chip in the chat names the clip or the range, and the agent's prompt carries the clip's id and name or the range, with a frame (two for a range).

A duration changed in the editor is your choice: the version stays complete even when it is far from the brief's duration, and the format view shows the brief's next to it ("7 s · brief 6 s (direct edit)"). The next agent turn is told to keep the current duration unless you ask for another one; update the brief's duration yourself if you want it to match.

Current limits: signed desktop builds depend on the maintainers' certificates (see Release). On Ubuntu 24.04 and later the AppImage may fail to start because the system restricts unprivileged user namespaces (AppArmor, `kernel.apparmor_restrict_unprivileged_userns`), which Chromium's sandbox needs: you need an AppArmor profile for the app (or, at your own risk, disable that restriction); avoid `--no-sandbox`, which removes the window's isolation.

## Security
- **Agent sandbox** (macOS; Linux with `bubblewrap` and `socat`): every agent job runs isolated. It can only write in the project folder and cannot read sensitive folders (`~/.ssh`, cloud credentials, keychains, the Motion Studio configuration). The network depends on the job: creatives and the console use only package registries, CDNs and the domains you add in **Settings → Network**; brand analysis has no network in the sandbox: it reads pages with `WebFetch` and downloads logos and fonts only with Motion Studio's `download_file` tool, which blocks private or local addresses (checked on the resolved IP, at every redirect); asset description has no network. The sandbox does not fall back to unrestricted execution: if it cannot start, commands do not run, and the agent cannot ask to run a command outside it.
- **Files that configure Motion Studio and the agent**: in every job, with or without the sandbox, the agent cannot modify the project's `.git/`, `.claude/`, `.studio/`, `CLAUDE.md`, `CLAUDE.local.md` and `.mcp.json`; Motion Studio runs git without the project's hooks.
- **Linked codebases**: readable, never writable (interpreters included, thanks to the sandbox); Motion Studio still reports it if a git codebase changes during a turn.
- **Codebases as brand sources**: read-only, no commands and no content search, secret files denied to the file tools and the sandbox, and the proposal discarded if the folder changes (see **Brand from a codebase**). The copy tool `import_codebase_file` checks every source after resolving links: inside the codebase, a regular file, not secret (in any letter case), an image or font extension.
- **Approvals**: anything outside the perimeter (e.g. installing a program, writing outside the project) appears as a request on the job's page and at the top right: *Allow once*, *Always for this project* (revocable in the project's settings) or *Deny*. "Always for this project" is offered only for a short list of safe commands (`ls`, `mkdir`, `ffprobe`, image optimizers), for folders outside sensitive locations and the workspace, for web domains and for paid providers; other commands are approved one at a time. Rules live in `<project>/.studio/permissions.json`, protected from the agent. With no answer within 10 minutes the request is denied.
- **Automatic approval of sandboxed commands** (**Project settings → Agent and approvals**, on by default, shared by every project): a shell command runs without asking only when all of these hold: it is a `Bash` command, the job runs in the sandbox, the setting was on when the job started and is still on, and the agent did not ask to run it outside the sandbox (`dangerouslyDisableSandbox`). This covers creatives, brand analysis and asset description. It is safe because an approved command still runs inside the sandbox (checked live: it cannot write outside the allowed folders or reach other sites even when approved). Under the same conditions, reading a file in Claude Code's own per-user temporary folder (`/tmp/claude-<uid>`, where the agent's check frames may land) is approved too, never the rest of the temporary folder; the agent is told to keep check frames in `creatives/<slug>/work/tmp/` inside the project, which is never versioned. Everything else still asks: other files outside the project, paid providers, new websites. Each command or read approved this way is listed in the conversation ("N commands ran automatically in the sandbox · Details", with a plain-language explanation and risk indicators) and, for brand analysis, on the analysis card and in the Analyses list of the Brand page (from the proposal's `log.jsonl`). The setting **applies to new jobs**: turning it on does not change jobs already running; turning it off takes effect at their next request.
- **Command explanations**: approval cards and automatic approvals describe the command in plain words with risk indicators (e.g. "Complex command", "Deletes files"), computed by Motion Studio from the command itself; when it cannot be sure, it says so and rates the command at least medium instead of guessing. The reason written by the agent is only shown as a quote ("The agent says: …") and never replaces the explanation. The full command is always available under **Show command**.
- **API keys**: in the system keychain (or in the `OPENAI_API_KEY`, `ELEVENLABS_API_KEY`, `PEXELS_API_KEY`, `UNSPLASH_ACCESS_KEY` environment variables); the agent never sees them: the key variables are removed from the agent's environment (and its MCP server's) and the MCP tools ask Motion Studio to call the providers.
- **Costs**: image, voice-over, sound effect and music generations ask for confirmation before each call, from the agent and from **Generate** in Assets alike (can be turned off in Settings with **Ask before using paid providers**).
- **Interface access code**: Motion Studio's APIs answer only to the interface opened from the terminal link (the code is in `ui-token` in the configuration folder). It is a defense against stray local requests, for example web pages open in the browser or programs that do not know the code; it is not a barrier against a process of the same user that can read the configuration folder.
- **Without the sandbox** (Windows, Linux without bubblewrap, or isolation turned off): Motion Studio uses the restricted command list of the previous phase and reports it in the Doctor and in Settings. Without the sandbox the allowed commands (node, python, npm/npx, pip, ffmpeg) can read and write anywhere and contact Motion Studio itself: use the sandbox. They can also read Motion Studio's configuration folder, including the interface token (`ui-token`) and the bridge tokens of the jobs running at that moment (`run/*.token`): with the first a program can use Motion Studio's whole interface, approvals included; with a bridge token it can act as that running job, in its project and with its tools (a paid call still asks for confirmation unless an "Always" rule exists). The agent's Read, Grep and Glob tools are denied on that folder in every mode, and a permission request that names a path inside it is refused without asking you; commands are not checked that way. In particular, an interpreter started by the agent could modify `.studio/permissions.json`: Motion Studio accepts only rules in the formats that "Always for this project" can produce (safe commands, folders outside sensitive locations and the workspace, web domains, provider confirmations), so the agent could grant itself those permissions or skip a provider's cost confirmation, but not go beyond those limits.
- **Workspace settings without the sandbox**: the agent's interpreters could also rewrite the workspace settings (`.studio/settings.json`). During an unsandboxed run Motion Studio uses the settings the run started with and puts the file back afterwards, with a warning in the chat. If it cannot, it holds the security-relevant fields (sandbox, approvals, paid-call confirmation, the live opt-ins, extra domains, model, concurrent jobs) at the stricter of its copy and the file, across restarts, and the Doctor says so until you save the settings. If even that copy cannot be kept, unsandboxed agent runs are refused until you save the settings in the app. This is best-effort detection, not a boundary: without the sandbox the agent runs with your file access, Motion Studio's own folders included.
- **Compositions (agent-written code that runs outside the sandbox).** A composition can contain HTML layers written by the agent, and Motion Studio renders it outside the sandbox, so it is isolated in four layers:
  - its own local server (the composition server), on a different origin from the interface, reachable only with a short-lived, read-only token scoped to one composition, which serves only the runtime and that composition's `assets/` and `layers/` (no links, no paths outside, DNS-rebinding check);
  - strict headers on every file: a Content-Security-Policy with no network (`connect-src 'none'`), HTML layers each in their own sandboxed frame;
  - in a render, a Chromium page with every request outside the composition server blocked (request interception plus a dead proxy), no WebRTC or workers reaching out, a time and memory watchdog, and the whole process group killed on cancel, timeout or crash. The desktop app uses hidden, isolated Electron windows, each on its own in-memory session; the CLI uses Chrome with a throwaway profile in the temporary folder;
  - in the interface, the live preview is an iframe with `sandbox="allow-scripts"` only (no `allow-same-origin`), on the composition server's origin, and the messages it sends are checked. The desktop app also cancels any request or navigation from a preview frame that leaves the composition server.

  A composition never gets the interface's token, the API keys or the network. Storyboard images are served through signed URLs that expire after a few minutes. Every Motion Studio API still needs the interface access code.
- **Unverified outputs:** without ffmpeg/ffprobe installed, Motion Studio cannot really check resolution and duration, and shows the outputs as "unverified".

|---|---|---|
| Images | OpenAI gpt-image-2 | `OPENAI_API_KEY` |
| Voice-over | OpenAI TTS, ElevenLabs | `OPENAI_API_KEY`, `ELEVENLABS_API_KEY` |
| Sound effects, music, voice list | ElevenLabs | `ELEVENLABS_API_KEY` |

Stock assets keep the attribution required by Pexels and Unsplash (`attribution` field in `assets/assets.json`). Details in [docs/providers.md](docs/providers.md).

- **Key checks**: in **Settings → Paid services**, saving a key (and the **Test** button of each row) tries it with free, read-only requests and shows what it can do, per capability: works, missing (with the permission to enable on the provider's site), not verified (only a paid generation can tell) or error (network, timeout, 5xx, rate limit). A key the provider does not know shows "The service does not accept this key". The results stay in Motion Studio's memory: never on disk, never with the key.
- **Services per creative**: the brief (in **New creative → More options**, in the brief editor, and behind the **Services** chip in the chat composer) says which external services the agent may use, per kind: images (Auto, OpenAI, Stock only, Off), voice (Auto, OpenAI, ElevenLabs, Off), music and sound effects (Auto, ElevenLabs, Off). Auto is the behavior from before. Motion Studio enforces the choice in every agent tool, before any confirmation or request: a kind turned off is refused, a chosen provider is never swapped for another, and one without its key is refused. The agent is told the choice and tells you to use the Services button when you ask for something that is off. A provider without its key, or whose key the check found lacking the permission (for example ElevenLabs without `text_to_speech` for voice), cannot be chosen, and the reason is shown. A change applies from the next message. **Generate** in Assets is not affected (it is your own action).

## Brand, assets and linked codebases
- **Brand**: palette, fonts, logos, tone, dos and don'ts, photographic style; each entry shows where it comes from (manual, website, image, codebase: "from codebase · `src/theme.css`"). The prose guidelines are in `brand/guidelines.md`.
- **Fonts**: **Typography → + Add from Google Fonts** searches the Google Fonts catalog, previews each family in its own face (served by Motion Studio, the page never loads Google), and adds the weights you tick (and italic) to `assets/fonts/` with origin `google-fonts`; the brand font is linked to its file. Adding a family that is already in the brand adds the new weights to it. **+ Add manually** still links your own files.
- **Sound**: the Brand page's **Sound** section holds the genre, the energy, the instruments to use and to avoid, and the brand voice, picked with the provider's key set: the ElevenLabs voices of the account, with previews, or OpenAI's fixed list (no previews: listening would be a paid call). The agent follows it when it chooses music, sound effects and voices.
- **Brand analysis**: add one or more websites (and reference images with "Use for brand analysis") and press **Analyze brand**. The analysis shows its phases (reading, fonts, colors, logos, tone, writing). Fonts come first: the `inspect_site_fonts` tool reads the site's HTML and stylesheets and tells which fonts it uses and where they come from; Google fonts are then fetched into `assets/fonts/`, self-hosted ones downloaded (with "license unknown" in the summary), Adobe and system fonts only named. The agent visits the sites, downloads useful assets into `assets/` and proposes changes: you apply them entry by entry, and manually entered entries are never removed. The agent works on copies: the brand kit, guidelines, sources and asset and reference metadata cannot be modified by the editing tools and, if the agent changes them anyway, Motion Studio reverts the change and reports it.
- **Brand from a codebase**: on the Brand page (the empty state, or **Add a source** in the Sources panel) pick **From a codebase** and choose the folder of your app or site (the desktop app has a folder picker; you can also type the path, and the codebases already linked to the project are offered as suggestions), with an optional note. Up to 5 codebases per brand, mixed freely with websites and images. The folder is checked like a linked codebase: an absolute path, never the disk root, your home, the project or the workspace (or a folder around them), never a codebase inside another one, Motion Studio's configuration folder or a private folder of your home (keys and credentials, `.config`, or anything under `~/Library`, iCloud Drive included). The agent then looks, in this order, for tokens and themes (`tailwind.config.*`, CSS variables, design-token files, Android `colors.xml`, iOS colour sets), fonts, logos and icons (`public/`, `assets/`, favicons, `AppIcon.appiconset`, `mipmap-*`, `manifest.json`) and the tone (README, marketing texts, store metadata). Logos and local font files are copied into `assets/brand/` or `assets/fonts/` with the `import_codebase_file` tool (origin `codebase`, at most 40 copies of up to 50 MB per analysis); Google fonts are fetched as for websites.
  - **Read-only.** The codebase is added to the agent read-only: editing tools are denied on it and, with the sandbox, the system blocks writes too. Motion Studio takes a snapshot of the folder before and after the analysis (git status with content hashes, ignored files and the git configuration included); if anything changed, or if the check cannot run after the analysis, the proposal is discarded and the error names the folder (the changed files are in the analysis notes). A folder that is not a git repository cannot be checked: the analysis says so. These checks only read the repository: git runs without optional locks, so it never rewrites your `.git/index`.
  - **No commands, no content search.** An analysis with a codebase has no `Bash` and no `Grep`, with or without the sandbox: the agent lists files with `Glob` and opens them by name with `Read`, only inside the codebase folders. Command and search requests are refused without asking you. `WebFetch` is there only when the analysis also has a website.
  - **Secret files are never opened.** `.env*`, `*.pem`, `*.key`, `*.p12`, `*.keystore`, `*.jks`, `id_rsa*`, `.npmrc`, `.netrc`, `.pypirc`, `credentials*`, `secrets*`, `*.mobileprovision`, `google-services.json`, `GoogleService-Info.plist` and `.git/` are denied to the agent's file tools, in any letter case, and also by the sandbox. The import tool refuses them too. Without the sandbox the analysis still runs, with a note that the exclusion holds only as a rule of the agent's tools, not as a barrier of the operating system. See the limits below for folder names that break these rules.
- **Assets and references**: upload files by dragging them, filter by type and origin, add descriptions and tags (also with **Describe with the agent**). Audio and video play in the asset's details (audio with its waveform); durations, sizes and dimensions are read from the files. **Rename file** renames an asset and updates the brand kit and the briefs that use it. Sort by date, name, type or duration ("Longest first").
- **Generate** (Assets): makes an image (OpenAI), a voice-over (OpenAI or ElevenLabs), a sound effect or a music track (ElevenLabs) straight into the library, after the usual paid confirmation. A tab is available only when its provider's key is set.
- **Linked codebases** (project or single-creative Settings): folders on your computer that the agent can read; editing tools are blocked on every turn and, if a folder is a git repository and shows changes after a turn, the conversation reports it. You cannot link the project or workspace folder, a folder that contains them, or a folder inside them, nor a folder whose path has glob characters (see **Current agent limits**).

With the sandbox on, interpreters cannot write into linked codebases. Without the sandbox, the rules block only the agent's editing tools: interpreters (for example node or python) could still write into the folder. Motion Studio detects and reports changes only in folders that are git repositories; for the others, changes would not be detected. Prefer linking git repositories with their changes already committed.

General advice: analyze only websites you trust.

## Current agent limits
- **Codebase folder names with glob characters are refused:** with Claude Code 2.1.300 the agent's file rules do not match when a codebase path has parentheses `(` `)` together with square brackets or braces (for example `app (old) [v2]`; checked live, `docs/superpowers/notes/2026-10-15-phase14-live-checks.md`), so the secret-file and read-only rules would not hold. Motion Studio therefore refuses to link, as a brand source or as a project or creative codebase, any folder whose path or real path contains `(` `)` `[` `]` `{` `}` `*` `?` or (on macOS and Linux) `\`. On Windows `\` is the path separator and is not refused; there the other characters are checked in each folder name, and the escaping of the agent's rules has not been verified on Windows. Rename the folder (or the parent folder that has them); a symbolic link with a plain name does not help, because the folder's real path is checked too. Codebases linked before this check are left out of turns, console runs and brand analyses, with a note in the conversation or the job.
- **Workspace and project folder names with glob characters are refused too:** the rules that keep the agent away from Motion Studio's own files (`CLAUDE.md`, `.mcp.json`, `.claude`, `.studio`, the logs) are path rules as well, so Motion Studio does not let you choose a workspace whose path or real path contains `(` `)` `[` `]` `{` `}` `*` `?` or (on macOS and Linux) `\`, nor create a project in one. On Windows the same rule-escaping has not been verified. For a workspace or project that already has such a path, every agent run (creative turns, the project console, brand analysis, asset descriptions, translations) is refused before it starts with a message naming the path, and the Doctor shows a warning; browsing, rendering and exporting still work. Rename the folder (or the parent folder that has them) and choose the workspace again. If your home folder or Motion Studio's configuration folder has such characters, nothing is refused, but the Doctor warns that the agent's deny rules on them (tokens, secret files) may not apply.
- **Identity formats in other languages:** a translated render of a logo, favicon or app icon makes only the main image, never the file set.
- **HTML layers hidden only by a clip:** in a render, an HTML layer that is invisible is skipped (not waited for) while it is out of frame or while its own `clip-path` leaves no area: an `inset()` whose opposite sides meet, a `circle()` or `ellipse()` with radius 0, or a `polygon()` collapsed onto one axis, in px or %. Other clips are still waited for: the clip of a parent other than the stage, and clip values with `calc()`, `var()`, `path()`, `url()` or `shape()`; if Chrome stalls on such a layer, the render fails after about 5 seconds with an error and a diagnosis instead of hanging.
- **Project console:** with the sandbox on, commands run isolated; outside the sandbox the agent can modify the project's files, but requests that need an approval appear in the interface (see Security).
- **Image, voice, sound, music and stock providers:** they are described in [docs/providers.md](docs/providers.md) but have not been verified live with real keys (tests use simulated responses). The key checks were tried live only against a simulated endpoint; Google Fonts and the site-font reading of the brand analysis were tried live (see `docs/superpowers/notes/2026-10-13-phase11-live-checks.md`).

```bash
pnpm install
pnpm dev                  # core (tsx watch, port 4317) + web (Vite, port 5173 with /api proxy); the core prints the link with the access code

pnpm --filter motion-studio-desktop dist:dir   # unpackaged app in apps/desktop/release (only this computer's architecture)
```

## Release
For maintainers. Align the version in `apps/desktop/package.json` and `apps/cli/package.json`, then create and push the matching `vX.Y.Z` tag: every job of the `.github/workflows/release.yml` workflow stops immediately if the tag does not match both versions. The workflow builds the desktop app on macOS (`arm64` and `x64`), Windows and Linux and creates a **draft** GitHub release with the installers (to be published by hand); in parallel, if `NPM_TOKEN` is present, it publishes `@motion-studio/cli` to npm (a failure in a desktop build does not block it). CI (`ci.yml`) runs the type check, the i18n check and the tests on every push to `main` and on pull requests.

Repository secrets used by the workflow (all optional: without them the build is unsigned or npm is skipped):
- macOS (signing and notarization): `MAC_CERT_P12_BASE64`, `MAC_CERT_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`. Without `MAC_CERT_P12_BASE64` signing is off; notarization runs only if the certificate (`MAC_CERT_P12_BASE64`) and all three `APPLE_*` secrets are present, otherwise it is explicitly off.
- Windows: `WIN_CERT_PFX_BASE64`, `WIN_CERT_PASSWORD`.
- npm: `NPM_TOKEN`.
- `GITHUB_TOKEN` is provided by GitHub Actions.
