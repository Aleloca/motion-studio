# Output contract

The contract describes what the agent must deliver at the end of every creative turn and how Motion Studio checks it. The text the agent reads lives in each project's `.studio/context.md` (generated by `packages/core/src/project-template.ts`); the check is in `packages/core/src/creatives/output-contract.ts`, the manifest schema in `packages/shared/src/creative.ts`.

## Folder structure

```
<project>/creatives/<date-title>/
  work/                 the agent's workspace: sources, scripts, local dependencies
  outputs/v1/           delivery of version 1
    <preset-id>.<ext>   one file for each requested format
    manifest.json
    .previews/          posters of videos, generated by Motion Studio (do not write here)
  outputs/v2/ ...
```

Every turn writes into a new `outputs/vN/` folder (the exact folder is given in the request to the agent). Files are named `<preset-id>.<extension>`, for example `instagram-reel-9x16.mp4`; ids come from the workspace's format catalog (`.studio/presets/formats.json`, editable from the interface).

## manifest.json

```json
{
  "schemaVersion": 1,
  "files": [
    { "format": "instagram-reel-9x16", "file": "instagram-reel-9x16.mp4", "width": 1080, "height": 1920, "durationSec": 15 },
    { "format": "instagram-image-1x1", "file": "instagram-image-1x1.png", "width": 1080, "height": 1080 }
  ],
  "tools": ["remotion"],
  "renderCommand": "npx remotion render Main ../outputs/v1/instagram-reel-9x16.mp4"
}
```

- `schemaVersion`: always `1`.
- `files[]`: `format` (preset id), `file` (name only, no subfolders or `/` or `\`; `.` and `..` not allowed), `width` and `height` (positive integers), `durationSec` (positive number, optional: videos only).
- `tools`: list of strings, empty by default.
- `renderCommand`: optional; the command to run in `work/` to regenerate the outputs. It is quoted on one line (no control characters, at most 300 characters) when formats are added.

A corrupt manifest is never rewritten by Motion Studio.

## Validation rules

After every turn `validateOutputs` checks each format requested in the brief. The messages are the ones the agent receives (and that appear in the version as "problems"). They are written in the language set in **Settings → Language** at the time of the check; the English texts are shown here, and the Italian catalog has the same messages. Problems saved in a version are never translated afterwards.

| Situation | Message |
|---|---|
| Manifest missing | `manifest.json is missing in <folder>` |
| Manifest unreadable or not matching the schema | `Invalid manifest.json: <detail>` |
| Id not in the catalog | `Unknown preset: <id> (not in the format catalog)` |
| Format not in the manifest | `Missing format <channel> · <name> (<id>)` |
| Listed file missing or irregular (a symlink does not count) | `File not found for <id>: <file>` |
| Extension not allowed by the preset | `<file>: extension .<ext> not allowed for <id> (allowed: …)` |
| File over the preset's maximum size | `<file>: <x> MB, maximum <y> MB` |
| With ffmpeg/ffprobe: file unreadable | `<file>: cannot be read as media` |
| Resolution different from the preset | `<file>: resolution <w>×<h>, expected <W>×<H>` |
| Video with no detectable duration | `<file>: does not look like a video` |
| Duration over the preset's maximum | `<file>: duration <d>s exceeds the maximum of <m>s` |
| Duration far from the brief's (difference above the greater of 1 s and 10%) | `<file>: duration <d>s, about <t>s requested` |

With ffprobe available, width, height and duration are the measured ones (not the declared ones) and the output is "verified"; for videos a poster is also extracted into `.previews/<file>.jpg`. Without ffprobe the manifest values are used and the output is shown as "unverified". For images, duration is always ignored.

## Fix attempts

If there are problems, Motion Studio restarts the agent (in the same session) with the list of problems and asks it to deliver again in the same folder, updating the manifest. Attempts are at most 3 in total (the first turn plus two fixes). The exception is problems that are only unknown presets: the agent cannot solve them, so there is no retry. At the end the version is saved as **complete** (no problems) or **incomplete** (problems left, listed in the version), always with a git commit.

## MCP tool `validate_output`

In creative turns the agent can call `validate_output` (`studio` MCP server, no parameters) to run the same check on the current version before closing the turn; it returns `outputs` and `problems`, but saves nothing and does not count as an attempt. Outside creatives it answers "Validation is only available in creatives" (in the current language).

## Export

The outputs of a version are copied with **Export…** under the names `<slug>-<format>-vN.<ext>`, without overwriting and refusing folders inside the workspace. Files that cannot be exported are reported as skipped. See the README.
